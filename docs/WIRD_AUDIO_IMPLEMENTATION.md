# تطوير صوت ورد الاستغفار — سجل تنفيذ

## الحدود
- التسجيل الأول يبدأ عند صفحة 4 والتسجيل الثاني عند صفحة 22.
- يعمل المشغل في قارئي PDF والصفحات المحلية Android والنسخة المكتبية Windows.
- تسجيل واحد فقط يعمل في أي لحظة داخل صفحة القراءة.
- حفظ موضع الاستماع اختياري محليًا ويمكن نسخه احتياطيًا؛ لا تُحفظ الملفات الصوتية ضمن النسخة الاحتياطية للمستخدم.
- الضغط على إشعار "الاستماع للحزب" يفتح المشغل المناسب، لكنه **لا يبدأ الصوت تلقائيًا**؛ يجب الضغط على تشغيل داخل التطبيق.
- لا تغير محتوى أو بصمات المصحف/الكتب أو مفتاح التوقيع الحالي.

## شرط استكمال الرفع
تتطلب النسخة الحقيقية إضافة ملفي MP3 الأصليين إلى \`public/audio/wird/\` بالحجم والبصمة المدرجين في \`public/audio/wird/README.md\`.
لم ينقل موصل GitHub المستخدم الملفات الثنائية من مرفقات المحادثة؛ لذا أبق هذا الفرع في حالة Draft حتى يتم رفعهما.
يوقف \`scripts/prepare-mobile-assets.mjs\` تجهيز Android/Windows إن لم يجدهما ويعيد \`scripts/verify-mobile-bundle.mjs\` فحص الأصول في \`dist-mobile\`.

## مصفوفة القبول
- [ ] رفع الملفين بلا أي تغيير ونجاح فحص SHA256 لكل منهما.
- [ ] قراءة صفحة 4 ثم تشغيل الأول، إيقافه، استئنافه، والتقديم 15 ثانية.
- [ ] قراءة صفحة 22 ثم تشغيل الثاني دون تداخل مع الأول.
- [ ] بقاء الصفحة وتفضيلات المستخدم سليمة بعد الخروج وإعادة فتح التطبيق.
- [ ] تذكيرا 09:00 و21:00 الافتراضيان، وتعديلهما وإيقافهما، وأزرار "فتح الورد"/"الاستماع".
- [ ] تشغيل التسجيلين في وضع الطيران على هاتف Android فعلي.
- [ ] تشغيل التسجيلين على Windows مثبت فعليًا، وتغيير الموضع في المشغل مع استجابة خادم loopback لمجال bytes.
- [ ] اختبارات الويب والمتصفح والهاتف والذاكرة وإمكانية الوصول، والتأكد من عدم التشغيل التلقائي.
- [ ] التحقق من أن التسجيل يوافق الحزب المنسوب إليه بصريًا ومسموعًا.
- [ ] بناء APK/AAB موقّع بالإصدار التالي وحفظ شهادة التوقيع نفسها، بعد قبول الأجهزة.

## اختبارات آلية
\`bun run test\`، \`bun run typecheck\`، \`bun run build\`، \`bun run mobile:build\`، واختبارات خادم سطح المكتب.
تحتاج \`mobile:build\` إلى جميع أصول المشروع الأخرى بالإضافة إلى الملفين الصوتيين.
