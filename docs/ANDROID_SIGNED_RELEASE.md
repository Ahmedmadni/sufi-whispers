# رحاب الخليلية — توقيع أندرويد سحابي بالكامل (بدون تثبيت على Windows)

**الإعدادات المعتمدة:** رحاب الخليلية · `com.rihabalkhaliliyya.app` ·
`1.0.0` (`versionCode=1`) · `rihab-production.jks` · alias `rihab-production`.

## ما أُنجز

- تجهيز إجراء GitHub Actions: **Initialize Rihab Signing Key (Cloud Only)** لتوليد مفتاح
  RSA-3072 فعلي داخل سيرفر GitHub لأول مرة، عبر Java JDK 21 المُثبت في GitHub Actions.
  **لا تحتاج إلى تثبيت Java أو Android Studio أو تنزيل ملف على جهازك.**
- يعمل الإجراء مرة واحدة ويمنع إعادة توليد المفتاح إذا كانت النسخة المشفّرة موجودة.
- تُحفظ **النسخة المشفرة فقط** في `config/rihab-production.jks.enc.json`،
  باستخدام AES-256-GCM مع scrypt وملح وnonce عشوائيين والتحقق من بصمة شهادة التوقيع.
  لا تُحفظ البايتات الأصلية للمفتاح أو كلمة الحماية داخل Git أو سجلات Actions.
- يتحقق إجراء **Android Signed Release Candidate** من كلمة الحماية في GitHub Actions Secrets،
  ويفك التشفير داخل بيئة تشغيل مؤقتة فقط، ثم يبني APK وAAB إنتاجيين بالمفتاح نفسه؛
  ويمسح الملف المؤقت عند النهاية.
- **إجراءات النشر لا تنشر تلقائيًا إلى متجر التطبيقات**، ويلزم اختبار نسخة موقعة
  على جهاز فعلي والموافقة عليها قبل توزيعها.

## المطلوب منك مرة واحدة فقط، عبر موقع GitHub (لا تنزيلات أو برامج)

افتح صفحة <https://github.com/Ahmedmadni/sufi-whispers/settings/secrets/actions>
واختر **New repository secret**:

- **Name:** `RIHAB_SIGNING_MASTER_PASSWORD`
- **Secret:** قيمة عشوائية قوية وفريدة من مدير كلمات مرور موثوق، بطول **40 حرفًا على الأقل**
  (ويُفضّل 50–64 حرفًا عشوائيًا). **احتفظ بها خارج GitHub أيضًا في مدير كلمات المرور الخاص بك**.
  لا ترسل هذه القيمة داخل دردشة، ولا تستخدم كلمة مرور حساب GitHub نفسه.
  لا تستخدم كلمة عامة أو جملة طويلة سهلة التخمين؛ لأن النسخة المشفرة موجودة في مستودع عام.

بعد حفظ السر، افتح:
<https://github.com/Ahmedmadni/sufi-whispers/actions/workflows/android-signing-bootstrap.yml>

واختر **Run workflow** على `main` ثم انتظر نجاح التنفيذ.

**ما الذي يحدث بعدها؟** يظهر ملف `config/rihab-production.jks.enc.json` داخل `main`
بوصفه نسخة مشفرة لا تكشف المفتاح الحقيقي. يعتمد تحديث التطبيق مستقبلاً على
**الاحتفاظ بنفس كلمة الحماية ونفس الملف المشفر**، مع زيادة `versionCode`.
لا تغير كلمة الحماية المخزنة في GitHub من تلقاء نفسك بعد إنشاء المفتاح؛ سيمنع ذلك فكّه
في الإصدارات التالية ما لم تُجرِ عملية إعادة تشفير مضبوطة.

## إصدار Android النهائي — شرط مستقل لسلامة القرآن

قبل تشغيل <https://github.com/Ahmedmadni/sufi-whispers/actions/workflows/android-release.yml>
يلزم أيضًا اعتماد SHA-256 مستقل لنص
`hafsData_v2-0.json` من المصدر الموثوق، وتسجيله ضمن GitHub Secret
`QURAN_EXPECTED_SHA256`. **لا يتم اختراع هذه القيمة أو تجاوز بوابة سلامة النص.**
بعد اعتمادها:

- شغّل **Android Signed Release Candidate** يدويًا على `main`.
- يتحقق GitHub من ملفات المصحف الـ604، والكتب السبعة ذات 1040 صفحة، وPDF Worker المحلي،
  ومن صحة توقيع APK وAAB ومعرف الحزمة ورقم الإصدار.
- تُحفظ APK/AAB الموقّعتان كمرفقات Actions مؤقتة لمدة 30 يومًا للمراجعة؛
  لا تُنشران تلقائيًا على Google Play أو GitHub Releases.

## الاحتياطي الأمني ومسؤولية المفتاح

- المستودع العام يحتوي **Ciphertext مشفرًا فقط** لا ملف `.jks` الأصلي؛ وقواعد
  `.gitignore` تمنع رفع ملف مفتاح خاص بالخطأ.
- ZIP المصدر لا يحفظ GitHub Secrets. **احفظ كلمة الحماية نفسها في مدير كلمات مرور آمن،
  واحتفظ بنسخة ثانية خارج حساب GitHub**. فقدانها يعني عدم إمكان استعادة مفتاح التوقيع
  من الملف المشفّر، ومن ثم قد يتعذر تحديث التطبيق بذات الهوية مستقبلًا.
- حساب GitHub يجب أن يكون مؤمّنًا بالمصادقة الثنائية.
- لا ترسل المفتاح أو كلمة حمايته داخل المحادثة أو البريد غير المشفر.
- لم يتم اختبار الإصدار الموقّع على هاتف فعلي بعد. نسخة Debug الحالية بتوقيع آخر؛
  لا يمكن تثبيت نسخة Release محلها كتحديث مباشر عادةً؛ صدّر بياناتك من صفحة
  `/settings` قبل إزالة نسخة Debug.
- راجع `docs/PROJECT_BACKUP_CHECKLIST.md` للنسخة الاحتياطية الكاملة،
  وخاصة أصول الكتب والصور والتوقيع وبيانات المستخدم.

## خيار Windows القديم

أداة `scripts/prepare-rihab-signing.ps1` موجودة لمن يريد العمل دون GitHub Actions،
لكنها **غير مطلوبة** عند استخدام المسار السحابي الموضح أعلاه. لا تخلط بين مفتاح
يولَّد على Windows ومفتاح يُولَّد في GitHub؛ فلكلٍّ منهما شهادة مختلفة.
