## ما تعالجه المرحلة 22

- تثبيت إصدار Bun في CI عند 1.4.3 المعتمد بآخر Build ناجح.
- استخدام إصدار Capacitor الدقيق 8.5.3 الذي نجح في بناء 11 أكتوبر، دون القبول التلقائي بأي تحديث 8.x أثناء تجهيز Android.
- إضافة بوابة إصدار عامة: `RELEASE_BUILD=1` يتطلب `QURAN_EXPECTED_SHA256` مرجعيًا صحيحًا للنص القرآني، ويفشل عند الغياب أو عدم المطابقة.
- تحديث الوثائق التي كانت تزعم أن بناء APK لم ينجح.

> ملاحظة: لم تُضف حزم Capacitor بعد إلى `package.json` و`bun.lock` في المستودع لأن اعتماديات أندرويد كانت تُثبت خلال عملية البناء؛ يستمر تثبيتها محليًا بإصدارات دقيقة. الحفظ الكامل لمشروع `android/` وتوقيع التطبيق مطلوبان قبل Release.

## بوابات الإطلاق المفتوحة

1. **P0 سلامة النص:** الحصول على بصمة SHA-256 الأصلية لملف Hafs JSON من جهة موثوقة مستقلة، ثم تشغيل `RELEASE_BUILD=1` واختبار ذلك في CI.
2. **P0 تجربة Android:** تثبيت التطبيق على هاتف فعلي، وضع طيران، تنقل المصحف وجميع الكتب والأذكار، الصوت، الاستعادة، الذاكرة.
3. **P0 نسخة Release:** اعتماد `applicationId`، حفظ مفاتيح التوقيع بأمان، توقيع APK وAAB واختبار التحديث وعدم فقدان البيانات.
4. **P1 الأدوات:** تثبيت الاعتماديات بقفل إصدار محفوظ، وتتبع مصدر Android native، وأرقام `versionCode/versionName`.
5. **P1 الأذكار:** تصحيح الاعتماد على أوقات 04:00 و15:00 و18:00 التقريبية؛ تحديد أوقات الفجر والعصر والمغرب حسب مدينة/تاريخ أو بإدخال قابل للتعديل مع توضيح المصدر.
6. **P1 بيانات المستخدم:** تصدير/استعادة نسخة احتياطية للعدّادات ومواضع القراءة.
7. **P2 التوزيع:** إصدار GitHub Release دائم بدل Artifact تنتهي صلاحيته بعد 7 أيام، ثم المتجر إن كان مطلوبًا.

## تعليمات البناء

```sh
bun install --frozen-lockfile
bun run test:integrity
bun run test
bun run typecheck
bun run build
# offline Quran / books fonts must be prepared as in android-debug.yml
bun run mobile:android:apk
```

**لإصدار عام فقط** بعد اعتماد البصمة وتوفير الملفات الأصلية:
```sh
RELEASE_BUILD=1 QURAN_EXPECTED_SHA256=<verified-publisher-sha256> bun run mobile:build
```

هذا الفحص ليس عملية توقيع Android، ولا ينبغي تسويق APK تجريبي على أنه نسخة إصدار عام.
