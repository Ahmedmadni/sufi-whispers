# رحاب الخليلية — قائمة النسخة الاحتياطية الكاملة للمشروع

> مهم: تصدير المستودع من GitHub لا يساوي نسخة احتياطية كاملة للمشروع.
> بعض الأصول تحفظ خارج GitHub، كما أن الأسرار ومفتاح التوقيع الخاص لا يمكن استردادهما من GitHub ZIP.

## 1) المصدر والكود
- نزّل ZIP من الفرع `main`، واحتفظ أيضًا بنسخة Git كاملة للفروع وتاريخ التعديلات إن أمكن.
- احتفظ بملفات `config/android-release.json`، و`capacitor.config.json` و`bun.lock`
  مع الكود. لا تحفظ `node_modules` أو مجلدات البناء المؤقتة بدلًا من المصدر.
- احتفظ بأرقام إصدار GitHub والـCommit المستخدم لكل إصدار APK وAAB.

## 2) أصول القراءة الأصلية وملفات الوسائط
- ملف القرآن النصي الأصلي `hafsData_v2-0.json` وملف الخط العثماني `uthmanic_hafs_v20.ttf`
  مسجلان بوصفهما أصولًا خارجية في ملفات `*.asset.json`. **قد لا يكون الملف الثنائي
  الأصلي موجودًا داخل ZIP المصدر**: احتفظ بنسخ الأصول الأصلية المرخّصة بشكل مستقل،
  مع توثيق مصدرها وتحقق البصمات SHA-256.
- مصحف المدينة المعتمد `MushafMadinaHafsGreen1441.pdf` له بصمة مصدر مثبتة
  `2f0b03925568fca326f47a5ec756df2c3eecc8b29f75471f3a0815a5a3e58d28`.
  الصور الأصلية الـ604 محفوظة في Commit ثابت
  `0b944b349fd28295803a0a96fbf2906a14286245`، **وليست كلها داخل ZIP الرئيسي**.
  احتفظ بالـPDF الأصلي ونسخة من الصور/الفرع المرجعي.
- المكتبة تضم كتاب PDF رئيسيًا `public/book.pdf` وسبعة كتب PDF إضافية تُستخدم
  منها صفحات محلية أثناء بناء Android. ملفات `*.asset.json` ليست الكتب نفسها:
  احتفظ بنسخة ثنائية من ملفات الكتب الأصلية.
- تحقق من العدد الفعلي للأصول في الحزمة: 604 صفحة مصحف و1040 صفحة للكتب السبعة.
  هذا **اختبار للحزمة المبنية** وليس إثباتًا أن ZIP المصدر يتضمن جميع الملفات.

## 3) مفتاح توقيع Android والأسرار (خارج مشروع GitHub)
- **في المسار السحابي الجديد:** بعد تشغيل `Initialize Rihab Signing Key (Cloud Only)`
  احتفظ بملف `config/rihab-production.jks.enc.json` المشفر ضمن النسخة الاحتياطية
  للمستودع؛ هذا الملف وحده **غير كافٍ** لاستعادة المفتاح دون كلمة
  `RIHAB_SIGNING_MASTER_PASSWORD` العشوائية (40 حرفًا أو أكثر).
  احفظ هذه الكلمة في مدير كلمات مرور آمن، مع نسخة استعادة خارج GitHub.
- في المسار المحلي الاختياري القديم فقط: احفظ
  `%USERPROFILE%\\RihabKeys\\rihab-production.jks` **بعد إنشائه بالفعل**؛
  هذا الملف غير متضمن في ZIP المستودع، ولا ترفع مفتاحًا خاصًا غير مشفر إلى GitHub.
  وجود اسمه في `config/android-release.json` لا يعني أنه أُنشئ.
- احفظ كلمة حماية السحابة أو كلمات مرور المفتاح المحلي في مدير كلمات مرور موثوق،
  مع خطة استرداد لا تعتمد على وصولك إلى GitHub وحده.
- أضف أسرار الإصدار في GitHub Actions، لكنها **لا تظهر داخل تنزيل GitHub ZIP**.
- احفظ ملف المفتاح في مكانين آمنين منفصلين؛ لا ترفعه إلى المستودع،
  ولا تضمه إلى أرشيف مشروع عام أو تخزين غير مشفر.
- احتفظ بصمة توقيع الشهادة المعتمدة بعد أول إصدار موقّع،
  واستخدم نفس المفتاح لتوقيع التحديثات المتوافقة في المستقبل.

## 4) إعدادات التشغيل والنشر
- سجّل الخدمات المتصلة والمجالات وإعدادات DNS والاستضافة ومصادر التحميل
  المستخدمة في `CONTENT_ASSET_ORIGIN`، مع خطة لاسترجاع الأصول إذا توقف المزود.
- سجّل قيمة `QURAN_EXPECTED_SHA256` المعتمدة ومصدرها المستقل قبل أي
  إصدار Production؛ **لا تخترع قيمة** لمجرد تجاوز بوابة سلامة النص.
- احتفظ بملفات APK/AAB الموقعة بعد إنتاجها؛ مرفقات GitHub Actions مؤقتة
  وقد تنتهي صلاحيتها تلقائيًا.
- البيانات الشخصية على هاتف المستخدم، مثل عدادات الذكر وإشارات القراءة،
  **ليست جزءًا من نسخة GitHub**. استخدم صفحة `/settings` لتصديرها محليًا
  قبل إزالة التطبيق أو الانتقال إلى هاتف آخر.

## 5) اختبار الاسترجاع
- جرّب إعادة بناء الموقع ونسخة Android Debug من الكود والأصول المحفوظة.
- راجع أن النسخة المسترجعة تتضمن الكتب والمصحف كاملين.
- اختبر استعادة بيانات المستخدم دون الحاجة إلى الاتصال بخوادم غير مضمونة.
- لا تعتبر النسخة **كاملة** حتى تستطيع استرجاع الملفات الثنائية الأصلية،
  والاعتماديات، ومفتاح توقيع الإنتاج المنفصل، وبيانات النشر المطلوبة.


## 6) نسخة الاسترجاع السحابية المؤتمتة (المرحلة 29)

- سير العمل `.github/workflows/cloud-project-backup.yml` يعمل بعد دمجه في `main`
  أو يدويًا من GitHub → Actions → **Verified Cloud Project Backup**.
  لا يلزم تنزيل أو تشغيل أي برنامج على Windows.
- ينشئ المرفق `rihab-complete-verified-cloud-recovery`، الذي يحتوي أرشيف
  `rihab-complete-cloud-recovery.zip`، وملف `SHA256SUMS.txt` وبصمة Commit.
- تشمل النسخة `repository/project-history.bundle` (تاريخ Git القابل للاستعادة)،
  والصور الأصلية الـ604 للمصحف من Commit المرجع الثابت،
  ومصادر الكتب السبعة بصيغة PDF والنص القرآني الأصلي والخطوط،
  وملف PDF الرئيسي ومصادر PDF.js، والصور المجهزة للقراءة دون إنترنت،
  وملفات الإثبات SHA-256.
- يتحقق البرنامج من كل صورة مصحف أصلية وبصمتها، و604 صورة مطابقة،
  وكل صفحات الكتب السبعة وعددها 1040، والمصادر الأصلية،
  ثم يعيد فتح أرشيف النسخة ويتحقق من بصمة كل ملف داخله.
- **الاحتفاظ مؤقت لمدة 30 يومًا فقط من GitHub Actions**، وقد تتغير مدة الاحتفاظ
  بحسب إعدادات GitHub. هذا مناسب كنسخة استرجاع سحابية مؤقتة، وليس حفظًا أبديًا:
  يجب نقل نسخة الأرشيف خارج GitHub Actions إلى موقع تخزين آمن ودائم قبل انتهاء مدته.
  ولم تُفعّل مزامنة Google Drive تلقائيًا.
- **الأرشيف لا يحتوي** أسرار GitHub، كلمة حماية التوقيع `RIHAB_SIGNING_MASTER_PASSWORD`،
  ملف التوقيع الخام، أو بيانات المستخدم على جهازه. وقد لا يحتوي ملف PDF الأصلي
  ذي 640 صفحة؛ لكنه يحتوي الصور الأصلية الـ604 التي يقرأ منها التطبيق
  مع بصماتها، ونسخة مصحف القراءة المُجهزة.
- **لا ترفع هذا الأرشيف إلى GitHub Release عام.** يحتوي نسخًا من كتب وأصول
  خارجية قد تخضع لشروط توزيع مختلفة، ويجب حفظه ضمن صلاحياتك فقط.

### خطوات الاستعادة من الأرشيف

1. تحقق من `SHA256SUMS.txt` بعد استرجاع الملفات.
2. افتح الأرشيف واستخرج `repository/project-history.bundle`،
   ثم استرجع المصدر عبر `git clone project-history.bundle recovered-repo`.
3. استخرج `mobile-public/` إلى `mobile/.public/` بالمشروع المستعاد؛
   يحتوي الأصول الأصلية وملفات القراءة المحفوظة.
4. استخرج `original-mushaf/` للاحتفاظ بالصور المرجعية الأصلية منفصلة.
5. شغّل فحوص الجودة والبناء والتوقيع المعتادة بعد توفير بيئة التطوير.
   يتطلب التوقيع الإنتاجي أيضًا نفس كلمة حماية المفتاح من خارج الأرشيف.

**حدود هذه النسخة:** لا تحفظ إعدادات استضافة Lovable أو أسرار النشر أو
بيانات حسابات الخدمات الخارجية. جميع هذه البيانات يجب توثيقها على حدة.
